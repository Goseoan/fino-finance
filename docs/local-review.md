# 공개 소스 검수 기록

검수일: 2026-11-21. 실제 계정·금융 자료를 사용하지 않고 별도 소스 사본과 합성 데이터만 검증했습니다.

## 검증

- 단위/정합성 테스트 54개 통과.
- 타입 검사 및 최종 프로덕션 빌드 통과.
- 추가 분류 기능 전 전체 브라우저 검사 39개 통과.
- 분류·그룹 추가 후 집중 회귀 9개 통과: 카드/그리드 일치, 사용자 분류/미분류 보존, 중복/누락, 검색, 소계, 용도 수동 지정, 금액 저장과 모바일 화면.
- 자산 그룹과 지출 그룹의 합성 자료 화면 검토.
- macOS 셸 실행 스크립트 구문 및 AppleScript 컴파일 확인.

## 공개 제외와 코드 정리

개인 기록·재무 합계·문서 ID·OAuth 클라이언트/토큰·개인 경로·개발 이력을 제외했습니다. 예제 설정은 빈 값으로 제공합니다. 사용자별 고정 문서 ID는 설정으로 대체하고 개인 설치 경로를 고정하지 않습니다. 테스트는 합성 자료이며 원본 로컬 저장소와 별도입니다. 운영 자료·백업·캡처·캐시·의존성은 공개 트리에 포함하지 않습니다.

공개 후보와 Git 스테이징/커밋 트리에서 개인 식별 문자열, 비밀키/토큰 패턴, 실제 Google 문서 링크, 개인 경로, 예기치 않은 바이너리/데이터 파일을 검사합니다. 새 저장소의 초기 커밋으로 구성하며 원본 작업 이력을 옮기지 않습니다.

## 남은 범위

- 정적 패턴 검사는 향후 추가되는 파일의 모든 개인정보를 자동 보증하지 않습니다. 추가 커밋마다 공개 범위를 다시 확인해야 합니다.
- 실제 Google 계정에 대한 OAuth·읽기·쓰기는 이번 합성 검증에 포함하지 않았습니다. 테스트는 SDK 모양의 대체 구현을 사용합니다.
- 신규 시트의 임의 형식 자동 매핑, 다중 사용자 인증, 은행 자동 조회는 제공하지 않습니다.
- 로컬 OAuth 파일은 소유자 파일 권한으로 보호하며 별도 암호화 저장소는 아닙니다. Google OAuth 범위는 앱 탭 하나만 허용하는 권한이 아니며 앱이 쓰기 범위를 제한합니다.
- 애매한 자동 분류는 검토 필요 또는 미분류로 표시합니다. 실제 기록을 추측 변경하지 않았고, 자산 유형의 표시 정규화는 원본 문자열을 바꾸지 않습니다.

과거 상세 이력 파싱·중복/모호한 이름 처리·0원/누락 구분·기존 스냅샷 우선·현재 잔액 보존·삭제/복원/영구삭제를 합성 자료로 검증했습니다. 항목 추이 4개 화면 검사와 과거 이력 표시/삭제 검사도 통과했습니다.

최종 회귀에서 자산/용도 `전체` 이름 충돌 수정, 과거 이력 삭제와 항목 추이 4개 화면을 포함한 집중 UI 8개가 통과했습니다. 기존 분류 집중 9개도 별도로 통과했습니다. 검증용 캡처·테스트 데이터는 공개 트리에서 제외합니다.

현금 세부 유형·사용자 지정 값 저장, 같은 날짜 두 번의 잔액 수정 전후 값 보존, 문서 인코딩/디코딩 후 이력 보존, 자산 영구삭제 시 이력 정리를 합성 자료로 검증했습니다. 수정 전후 이력은 기능 적용 이후부터 생성하며 과거의 존재하지 않는 수정 값을 복원했다고 주장하지 않습니다.

현금 세부 유형과 잔액 수정 이력의 최종 브라우저 집중 검사 9개 통과: 같은 날짜 두 번 수정 후 새로고침해도 전후 금액 두 건이 유지되는 것을 저장소 응답과 이력 차트에서 확인했습니다. 최종 단위54개·타입 검사·빌드도 통과했습니다.

고정지출·대출 이력 확대: 인라인/폼 변경의 전체 전후 값, 납부주기별 환산, 대출 필수 정보 미확인의 null 처리, 문서 저장 형식 왕복, 이력 복원 순서, 삭제·복원·영구삭제를 단위 검사로 확인했습니다. 신규 브라우저3개(저장 후 새로고침·지표 전환·모바일 빈 이력)와 기존 집중 회귀5개를 통과했습니다. 기존 자료를 기준값으로 일괄 기록하거나 수정 값을 되돌리는 기능은 추가하지 않았습니다.

## SQLite 기본 저장소 전환

Node.js 24 내장 SQLite를 기본 저장소로 바꾸고 ExcelJS 내보내기와 명시적 Google 전송을 추가했습니다. 새 설치는 빈 로컬 DB로 시작합니다. SQLite 트랜잭션·재시작·파일 권한·이관 충돌·복수 연결의 stale 수정·중간 SQL 실패 롤백을 합성 자료로 검증했습니다. 원본 작업본과 이관 캡처는 삭제하거나 변경하지 않습니다.

최종 단위 검사 59개와 타입 검사를 통과했습니다. 집중 브라우저 회귀는 관리 화면 18개·항목 추이 4개·저장/엑셀 2개·API 2개를 확인했습니다. 없어진 최초 저장소 선택 UI를 찾던 기존 검사 2건은 SQLite 기본 저장 방식에 맞게 수정하고 재실행해 통과했습니다. Google 인증이 유효하지 않아도 로컬 수정·Excel 다운로드가 동작하는지 확인했고, 모바일 설정 화면을 검토했습니다.

엑셀 8개 시트의 숫자 0·알 수 없는 빈 값·한글·수식처럼 보이는 이름의 문자열 처리·관측값 행 수를 검증했습니다. Google 전송은 합성 SDK로 원자적 상태/보고서 쓰기, 소유권, 미리보기 충돌, 요청 중복 방지를 확인했습니다. 실제 금융 자료를 Google에 보내는 검사는 수행하지 않았습니다.

Google 전송은 앱 전용 범위의 보관본을 교체하는 수동 동작이며 양방향 동기화가 아닙니다. 기존 관리·날짜 탭은 유지합니다. 현재 문서 포맷의 크기 제한과 조회용 표 5,000행 제한을 넘으면 전송을 중단하며 조용히 잘라내지 않습니다. JSON 백업과 Excel 내보내기는 별도로 사용할 수 있습니다. DB와 OAuth 파일을 별도 암호화하는 기능은 제공하지 않습니다.

최종 프로덕션 빌드가 경고 없이 통과했습니다. Next.js의 동적 파일 추적에서 런타임 자료를 배포 파일에 넣지 않도록 읽기 경로를 제외하고, `.data`·환경 파일·검사 산출물을 전체 서버 trace에서 제외했습니다. 생성된 서버 trace 19개에 실행 자료 경로가 없는 것을 확인했습니다.
